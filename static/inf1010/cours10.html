1. Membres statiques : partagés par toute la classe

Un attribut static est une variable de classe : il existe en un seul exemplaire, partagé par tous les objets, et même sans aucun objet. Une méthode static appartient à la classe : elle n'a pas de this et ne peut utiliser que les membres statiques. Usage typique : compter les instances, attribuer des identifiants uniques, constantes de classe, fabriques.

  • La définition int Joueur::nombre_ = 0; va dans le .cpp (sinon « symbole externe non résolu » ; dans le .h, elle serait dupliquée dans chaque fichier qui l'inclut). Depuis C++17, inline static int nombre_ = 0; dans la classe évite cette ligne.
  • Une méthode statique peut être appelée sans objet : Joueur::getNombre(). Elle ne peut pas être const ni virtual.
  • Variable locale static dans une fonction : initialisée une seule fois, conserve sa valeur entre les appels (compteur d'appels). Fonction libre static : visible uniquement dans son fichier.
  • Dans le simulateur de hockey, l'index affiché devant chaque joueur disponible ([0] 27 Kovalev) est attribué « par l'entremise d'une variable static dans la classe Joueur ».

2. Gestion des exceptions

Une exception signale une erreur à l'endroit où elle est détectée (throw) et la traite à l'endroit où l'on sait quoi faire (catch), même plusieurs appels de fonction plus haut. Entre les deux, les fonctions sont quittées une à une (dépilement) et leurs objets locaux détruits normalement. C'est l'alternative aux codes de retour qu'on oublie de tester.

Règles
  • Les blocs catch sont essayés dans l'ordre ; le premier dont le type correspond (type exact, ou classe de base avec une référence) gère l'exception, les autres sont ignorés. Un catch de la base placé avant celui de la dérivée rend ce dernier inatteignable (avertissement).
  • Une exception non attrapée remonte à l'appelant, puis à son appelant, jusqu'à main ; si personne ne l'attrape, std::terminate() arrête le programme.
  • throw; seul dans un catch relance l'exception courante vers le niveau supérieur (après un traitement partiel : journal, nettoyage).
  • Lancer par valeur, attraper par const&.
  • Un constructeur peut lancer : l'objet n'est pas créé (pas de destructeur appelé pour lui, mais ses attributs déjà construits sont détruits). Un destructeur ne doit jamais laisser sortir une exception (terminate).
  • noexcept marque une fonction qui promet de ne pas lancer.

La hiérarchie standard et vos propres exceptions

Dépilement et libération des ressources

Quand une exception traverse une fonction, ses variables locales sont détruites : un unique_ptr ou un vector libère sa mémoire, un ofstream ferme son fichier. Un pointeur brut, lui, n'est pas suivi d'un delete : fuite. C'est le principe RAII (l'acquisition d'une ressource est son initialisation, sa libération est dans un destructeur) et une raison de plus d'utiliser les pointeurs intelligents.

3. Introduction à Python

Python reprend les mêmes idées (classes, héritage, polymorphisme, exceptions, conteneurs) avec une syntaxe plus légère : pas de déclaration de types, pas de point-virgule, les blocs sont délimités par l'indentation, et la mémoire est gérée automatiquement (chaque variable est une référence, comme un shared_ptr). Le document « Passer de C++ à Python » du cours et le TP5 couvrent cette partie.

Différences qui piègent
  • L'indentation est la syntaxe : un bloc mal indenté est une erreur ou change le sens du programme.
  • b = a ne copie pas une liste ou un objet : les deux noms désignent le même objet (b.append(1) modifie aussi a). Copier : b = list(a), a[:], copy.copy, copy.deepcopy.
  • Pas de surcharge de fonctions par type : un seul def f par nom (le dernier gagne) ; on utilise les valeurs par défaut ou isinstance.
  • Les attributs ne sont pas déclarés : une faute de frappe dans self.puisance crée un nouvel attribut au lieu de signaler une erreur.
  • Division : 7 / 2 vaut 3.5 ; 7 // 2 vaut 3. == compare les valeurs, is l'identité.

4. À retenir

  • static : un seul exemplaire par classe ; définir la variable dans le .cpp (int C::x_ = 0;) ; méthode statique sans this, appelée C::f().
  • throw objet; ; try { } catch (const T& e) { } dans l'ordre, dérivées avant bases, catch (...) en dernier, throw; pour relancer ; e.what(). Non attrapée : terminate. Les destructeurs s'exécutent pendant le dépilement : pointeurs intelligents sûrs, pointeurs bruts fuient.
  • Classe d'exception : dériver de std::exception ou de std::runtime_error (message dans le constructeur).
  • Python : indentation, pas de types, self, __init__, super().__init__(), méthodes toutes virtuelles, __str__, listes et dictionnaires, raise / except, références partagées.

Quiz rapide - Module 10

Combien d'exemplaires d'un attribut static int nombre_; existent pour 5 objets de la classe ?

  • 5
  • 6
  • 1
  • 0 tant qu'aucun objet n'est créé
Un seul, partagé, qui existe même sans objet.

La classe déclare static int nombre_; et l'utilise dans son constructeur. L'édition des liens échoue : « symbole externe non résolu Joueur::nombre_ ». Pourquoi ?

  • Il manque static devant l'utilisation
  • La définition int Joueur::nombre_ = 0; manque dans le .cpp
  • nombre_ doit être public
  • Les attributs statiques doivent être const
La déclaration dans la classe ne réserve pas de mémoire ; la définition hors classe le fait, une seule fois.

Que ne peut pas faire une méthode statique ?

  • Être appelée sans objet
  • Accéder aux attributs statiques
  • Être publique
  • Utiliser this ou les attributs non statiques
Elle appartient à la classe, pas à un objet.

Qu'affiche ce programme ?

  • ac (et un avertissement : le second catch est inatteignable)
  • rc
  • abc
  • arc
Le premier catch compatible gagne : runtime_error dérive d'exception. Mettre les dérivées en premier.

Que se passe-t-il si une exception n'est attrapée par aucun catch, jusque dans main ?

  • Elle est ignorée
  • Le programme continue après l'instruction fautive
  • std::terminate() arrête le programme
  • main la retourne comme code d'erreur
D'où l'intérêt d'un catch (...) ou catch (const exception&) dans main pour un arrêt propre.

Pourquoi attraper par const T& plutôt que par valeur ?

  • Par valeur ne compile pas
  • Pour éviter une copie et surtout le découpage : catch (exception e) perdrait la partie dérivée et e.what() donnerait le message de la base
  • Pour pouvoir modifier l'exception
  • Parce que les exceptions sont des pointeurs
Même règle que pour le polymorphisme : référence, pas copie.

Une fonction alloue Robot* r = new Robot;, appelle une fonction qui lance une exception, puis fait delete r;. Que devient le robot ?

  • Il est détruit par le dépilement
  • Il est détruit par le catch
  • Le programme plante
  • Il fuit : le delete n'est jamais atteint ; un unique_ptr l'aurait libéré
Seuls les objets locaux (et ce que leurs destructeurs libèrent) sont nettoyés pendant le dépilement.

À quoi sert throw; (sans argument) dans un catch ?

  • À relancer l'exception courante vers l'appelant après un traitement partiel
  • À lancer une exception vide
  • À arrêter le programme
  • À revenir au début du try
Utile pour journaliser puis laisser un niveau supérieur décider.

Comment définir une classe d'exception avec un message ?

  • class E { string msg; }; puis throw E;
  • exception E("message");
  • class E : public std::runtime_error { public: E(const string& m) : std::runtime_error(m) {} };
  • typedef string E;
what() est hérité ; un catch (const exception&) l'attrape aussi.

Que fait vector::at(i) avec un indice invalide ?

  • Retourne 0
  • Lance std::out_of_range
  • Comportement indéfini
  • Agrandit le vecteur
Contrairement à []. out_of_range dérive de logic_error, elle-même dérivée d'exception.

En Python, que fait b = a si a est une liste ?

  • Copie la liste
  • Erreur
  • Crée une liste vide
  • Fait de b un second nom pour la même liste : modifier b modifie a
Comme copier un shared_ptr. Pour copier : b = list(a) ou copy.deepcopy(a).

Comment une classe Python appelle-t-elle le constructeur de sa classe de base ?

  • super().__init__(args) dans __init__
  • Automatiquement, toujours
  • Base::Base(args)
  • this.Base(args)
Contrairement à C++, l'appel n'est pas automatique si la dérivée définit son propre __init__.

Quel est l'équivalent Python de operator<< pour afficher un objet avec print ?

  • __print__
  • __cout__
  • __str__ (ou __repr__)
  • to_string
print(obj) appelle str(obj), donc __str__.

En Python, une méthode redéfinie dans une classe dérivée est-elle appelée via une variable qui contient l'objet dérivé ?

  • Seulement si elle est déclarée virtual
  • Oui, toujours : toutes les méthodes sont « virtuelles », le type réel décide
  • Non, sauf avec un cast
  • Seulement pour __str__
Il n'y a pas de type déclaré, donc pas de liaison statique possible.

Que vaut [n * 2 for n in [1, 2, 3] if n != 2] ?

  • [2, 4, 6]
  • [1, 3]
  • [2, 6, 4]
  • [2, 6]
Compréhension de liste : filtre puis transformation, l'équivalent de copy_if + transform.
