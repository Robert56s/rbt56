1. Les algorithmes : des boucles toutes faites

Un algorithme de la STL est une fonction générique qui travaille sur un intervalle d'itérateurs [debut, fin[, donc sur n'importe quel conteneur (et même sur un tableau C). Beaucoup prennent en plus une fonction (prédicat, opération, comparateur) qui décide quoi faire de chaque élément. Remplacer une boucle par un algorithme rend l'intention lisible (« compter », « chercher », « transformer ») et évite les erreurs d'indices.

2. Foncteurs : des objets qui s'appellent comme des fonctions

Un foncteur (objet-fonction) est un objet d'une classe qui surcharge operator(). On l'utilise comme une fonction, mais il peut avoir des attributs : un seuil, un compteur, un flux de sortie. C'est la façon classique de paramétrer un algorithme avec un état.

  • Foncteurs standard de <functional> : less<T>, greater<T>, plus<T>, minus<T>, multiplies<T>, equal_to<T>, logical_not<T>. Exemple : accumulate(b, e, 1, multiplies<int>()) pour un produit.
  • Un comparateur doit définir un ordre strict : a < b, jamais <= (sinon comportement indéfini de sort et des set).
  • operator() est const pour un prédicat ou un comparateur (l'algorithme peut recevoir une copie constante) ; non const si le foncteur accumule.

3. Fonctions lambda

Une lambda est un foncteur anonyme écrit sur place : le compilateur génère la classe (avec operator() et des attributs pour les captures) à votre place. Syntaxe : [captures](paramètres) -> type_de_retour { corps }. Le type de retour est déduit s'il est omis.

CaptureEffet
[]aucune variable extérieure (seules les variables globales et les paramètres sont accessibles)
[x]x copiée au moment de la création ; non modifiable dans la lambda sauf mutable
[&x]x par référence : modifications visibles à l'extérieur ; x doit survivre à la lambda
[=] / [&]toutes les variables utilisées, par valeur / par référence
[this]accès aux membres de l'objet courant (dans une méthode)
[=, &total]mixte : tout par valeur sauf total par référence
  • Chaque lambda a un type unique et anonyme : on la reçoit dans un paramètre générique (template <typename Fonction>, comme sommer au TP3) ou dans un std::function<bool(int)> (<functional>), qui peut aussi contenir une fonction ou un foncteur.
  • Lambda générique (C++14) : [](const auto& c) { ... } : le paramètre est déduit, pratique pour les shared_ptr.
  • Quand choisir ? Lambda : court, local, à usage unique. Foncteur : réutilisable, nommé, avec état ou plusieurs méthodes. Pointeur de fonction : fonctions existantes sans état.

4. À retenir

  • Algorithmes sur [begin, end[ ; retour : itérateur (end si absent), nombre, booléen. back_inserter pour remplir un conteneur vide, ostream_iterator pour afficher.
  • remove / remove_if / unique ne suppriment pas : c.erase(remove..., c.end()).
  • Foncteur = classe avec operator() ; peut avoir un état ; for_each le retourne. Comparateur : ordre strict, const, type passé en paramètre de template pour set / map / priority_queue.
  • Lambda [captures](params) { corps } ; par valeur (copie figée) ou par référence ; [this] dans une méthode ; mutable pour modifier une capture par valeur ; type unique → auto, template ou std::function.

Quiz rapide - Module 9

Que retourne find(v.begin(), v.end(), 42) si 42 est absent ?

  • nullptr
  • v.end()
  • -1
  • Une exception
Toujours tester if (it != v.end()) avant de déréférencer.

Après remove_if(v.begin(), v.end(), pred) seul, la taille de v :

  • Diminue du nombre d'éléments retirés
  • Devient 0
  • Ne change pas : les éléments à garder sont compactés au début, il faut appeler erase avec l'itérateur retourné
  • Double
C'est l'idiome erase-remove.

Qu'est-ce qu'un foncteur ?

  • Un objet d'une classe qui surcharge operator(), utilisable comme une fonction et pouvant avoir un état
  • Un pointeur de fonction
  • Une fonction générique
  • Une méthode statique
Exemples standard : greater<int>, less<T>, plus<T>.

Pourquoi Compteur c; for_each(v.begin(), v.end(), c); c.get(); retourne-t-il 0 même si des éléments ont été comptés ?

  • for_each ne fonctionne pas avec des foncteurs
  • get() est const
  • operator() n'a pas été appelé
  • Le foncteur est passé par valeur : for_each travaille sur une copie, qu'il retourne ; il faut récupérer cette copie
Compteur r = for_each(...); r.get();

Quelle lambda capture total de façon à le modifier ?

  • [total](int n) { total += n; }
  • [&total](int n) { total += n; }
  • [=](int n) { total += n; }
  • [](int n) { total += n; }
Par valeur, total est une copie constante (erreur de compilation sans mutable, et même avec mutable l'original ne change pas). Sans capture, total n'est pas accessible.

Que vaut x à la fin ? int a = 1; auto f = [a]() { return a; }; a = 7; int x = f();

  • 7
  • Erreur de compilation
  • 1 : la capture par valeur copie a au moment de la création de la lambda
  • 0
Avec [&a], x vaudrait 7.

Quel comparateur est correct pour trier des robots par masse croissante ?

  • [](const Robot& a, const Robot& b) { return a.getMasse() < b.getMasse(); }
  • [](const Robot& a, const Robot& b) { return a.getMasse() <= b.getMasse(); }
  • [](Robot a, Robot b) { return a < b; }
  • [](const Robot& a) { return a.getMasse(); }
Deux paramètres, ordre strict (jamais <=), par référence constante pour ne pas copier.

Que calcule accumulate(v.begin(), v.end(), 0) pour vector<double> v = {0.5, 0.5} ?

  • 1.0
  • Erreur de compilation
  • 2
  • 0 : la valeur initiale 0 est un int, les additions se font en int (troncature)
Écrire accumulate(v.begin(), v.end(), 0.0).

À quoi sert back_inserter(w) ?

  • À insérer au début de w
  • À fournir un itérateur de sortie qui fait push_back dans w à chaque écriture (w peut être vide)
  • À trier w
  • À retirer le dernier élément de w
Sans lui, copy(b, e, w.begin()) sur un w vide écrirait hors du conteneur.

Comment stocker une lambda dans un attribut de classe ?

  • lambda f_;
  • auto f_;
  • std::function<bool(int)> f_;
  • Impossible
auto n'est pas permis pour un attribut non statique ; std::function accepte lambdas, foncteurs et fonctions de signature compatible.

Que fait transform(v.begin(), v.end(), v.begin(), f) ?

  • Remplace chaque élément par f(élément), sur place
  • Trie v selon f
  • Retire les éléments pour lesquels f est faux
  • Copie v dans f
Le troisième argument est la destination ; ici le conteneur lui-même.

Dans une méthode de Robot, une lambda a besoin de l'attribut facteur_. Quelle capture ?

  • [facteur_]
  • [&facteur_]
  • Aucune : les attributs sont toujours visibles
  • [this] (ou [=] / [&], qui capturent this implicitement)
Un attribut n'est pas une variable locale : on capture l'objet courant.

Quel algorithme remplace cette boucle ? bool ok = true; for (const auto& m : membres) if (m->getSalaire() > cap) ok = false;

  • count(...)
  • bool ok = none_of(membres.begin(), membres.end(), [cap](const auto& m) { return m->getSalaire() > cap; });
  • find(...)
  • sort(...)
Ou all_of avec le prédicat inverse (<= cap).
